# Project Spark — Full Level 110 Layout Builder (V2.1 add-on)

## What this fixes

The existing v2 automatic generator produces an **empty gameplay scaffold** (`L110_PWR18_EMPTY_GAMEPLAY_AUTO_GENERATED.prefab`) containing 130 footprints and limited placeholders, whereas previous `Level_103_Layout.prefab` and `Level_104_Layout.prefab` contain significantly more hierarchy (physical pads, solver topology, copper, instrument UI, etc.). This patch adds a **new generator menu** producing `Level_110_Layout.prefab` and `Level_110_Layout.unity`, without altering the v2 empty-playable prefab or earlier levels.

## Install into your current Unity project

1. Back up the project and **close Unity**.
2. Extract this upgrade ZIP outside Unity.
3. Use PowerShell from the extracted folder (replace the example project root):

```powershell
.\Install_Full_Level_Layout_Upgrade.ps1 -UnityProjectPath "D:\\YourUnityProject"
```

Or copy these two scripts into the **existing** AutoLevelGenerator `Runtime` and `Editor` folders (do not create a second copy of the generator). Your installation appears to be under `Assets/My_Assets/_Project_Spark/Scripts/ProjectSpark/AutoLevelGenerator/`.

4. Reopen Unity. Import the Level 110 ZIP first in the existing v2 generator if you have not already: `ProjectSpark_Level110_PWR18_Assets_168_With_Complete_Board.zip`.
5. After C# finishes compiling, choose:

`Tools > Project Spark > Automatic Level Generator > Build FULL Level 110 Layout`

6. Find generated output under:

`Assets/ProjectSpark/AutoGeneratedLevels/Level110/Level_110_Layout.prefab`

and a matching `.unity` scene plus `Level_110_Layout_Validation.txt`.

**Do not drag the old `L110_PWR18_EMPTY_GAMEPLAY_AUTO_GENERATED` prefab into the full layout**: it already has its own root and targets. Use the new `Level_110_Layout.prefab` instead.

## Generated hierarchy

```text
Level_110_Layout
├── L110_BoardPhysicalRoot
│   ├── L110_BoardArtRoot                    (bare board and permanent FBX geometry)
│   ├── L110_ComponentSlots                  (130 colliders + target scripts)
│   ├── L110_PhysicalPads_SCHEMATIC_REQUIRED (not fabricated)
│   ├── L110_SolverTopology_SCHEMATIC_REQUIRED (not fabricated)
│   ├── L110_PlayerCopper                    (172 source-backed tasks grouped by subsystem)
│   ├── L110_ViaSockets_SCHEMATIC_REQUIRED   (56 source-backed tasks)
│   ├── L110_CopperLayers_VisualReference    (12 optional visual meshes)
│   ├── L110_ServiceableCooling             (removable cooling art, off by default)
│   ├── L110_RepairTargets                  (3 fault records)
│   ├── L110_InstrumentationAnchors         (12 tool binding locations)
│   ├── L110_PowerIntegritySimulation_BindExistingSolver
│   ├── L110_Objectives_BindLevelGamePlayManager (6 objectives)
│   ├── L110_W173_IndependentSafety         (pending real pin-level mapping)
│   └── L110_PowerIntegrityControls_WorldSpaceUI_BindExisting (26 actions)
├── L110_CompleteAssembledReference_NoProgress (disabled by default)
│   ├── L110_Modular_130Parts_Reference
│   └── L110_FullAssembledFBX_Reference
└── L110_InspectionLighting
```

The assembly reference includes either the one-piece assembled FBX, or the component-level composition if the assembled asset is unavailable. It is disabled during gameplay and **never** awards components, routes, vias, objectives or safety reset.

## Important limitations

- This is an **in-Unity generator**, not a fully baked `.prefab` preconstructed without your project's FBX GUIDs. Unity must import the models first to establish references safely.
- Exactly 130 component slots, 172 route task entries, 56 via task entries, three faults and six objectives are generated. These are inspector-visible source-backed objects; route/via names are not fabricated circuit wires.
- The Level 110 data does **not** include validated part pad numbers, actual pin-level netlist, source/destination route coordinates, or via locations/layer spans. The generator refuses to invent connections; physical pads/solver topology must be bound to actual Project Spark systems before the level is fully playable.
- The generated world-space control entries are named binding targets, **not functional Unity UI buttons**. Link them to the existing Project Spark UI controller and simulation services.
- FBX geometry is procedural, not yet hand-finished AAA art. Unity FBX import, compiler, rendering, and Play Mode still require actual in-project testing.
- Regeneration is destructive **only** to the generated `Level_110_Layout.prefab`/`.unity`; it asks before overwriting. It never edits Levels 103, 104, or prior level scenes.

## What you need for true 103/104 parity

Inspect the real Project Spark source scripts and bind: `SparkSelectionController`, the real terminal/pad representation, actual solver graph, placement/solder authority, route/via construction, tool UI, fault controllers, saved progress, `LevelGamePlayManager`, and the W173 supervisor. Never use the serialized script GUIDs from Levels 103/104 on different objects without proper type/field mapping.
