# Visual Architect acceptance checklist

1. Compile in the actual Unity 6.3 URP project. Verify no namespace conflicts or duplicate source copies. Open tool in edit mode. Do not use -nographics.
2. Scan existing campaign. Verify expected 123/690 only for original uploaded snapshot. Check Level 32 resolves to optical sorter. Missing/duplicate/blocked entries cannot be approved. Add a future valid test definition and confirm it appears, not auto-approved.
3. Select actual visual-only prefab for one known level. Confirm approval records its definition GUID. Test ambiguous candidates and inspect review; no source is silently bound.
4. Render one approved small circuit and one complex board/industrial prefab. Confirm five PNGs have original dimensions 1024x576, 1920x1080, 1024x1024, 1920x1080, 1920x1080. Inspect crop, materials, color space, shadows and subject accuracy. Verify prefab scripts did not run, original scenes are unchanged and camera resources are cleaned up.
5. Build missing/changed again; unchanged files and hashes stay unchanged. Modify a material dependency and rerun; affected levels regenerate. Change camera settings; affected approved levels regenerate. Reassign source; existing generated assets replace only if owned. Delete one generated PNG via Unity and rerun; repair all five as a set. Change definition GUID and confirm binding needs review.
6. Put an externally edited PNG in an output path. Generate with replacement off; verify it is preserved and the report identifies the block. Explicitly approve replacement, confirm backups of PNG and .meta. Inject a write/import fault in a test copy; verify original files restored. Cancellation between levels preserves completed results.
7. Preview panel in Play Mode. Every generated thumbnail assigned to correct key. Detail banner loads on selection, thumbnail fallback for missing banner. Cycle all 6 themes, filter, search, page, resize. Confirm locked/unverified launch still blocked. Profile Resources texture retention, texture build size and mobile scrolling. Loading and portrait images not wired into a gameplay screen by this upgrade.
8. Verify invalid sources: disabled mesh, no renderer, missing shader, excessive magenta and graphics device null. A failed capture must not overwrite good output. Inspect real legitimate magenta cases manually (heuristic may reject them).
9. Toggle auto rendering only after manual tests. Import a changed mesh/material and check incremental render; generated output imports must not create an endless regeneration loop.
10. Validate visual library. Report current/missing/stale entries and manually approve visual quality. Never claim all 130 artworks exist until local build confirms it.
