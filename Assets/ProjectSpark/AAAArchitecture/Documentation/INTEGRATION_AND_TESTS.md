# Project Spark AAA | Integration contract and release verification

## 1. Architecture boundaries

Keep SparkLevelDefinition, SparkLevelSelector, LevelGamePlayManager, SparkCircuitSystem, SparkElectricalNetworkGraph, SparkMeasurementSystem, SparkSelectionController and the existing save/progression provider authoritative. Never add another completion manager or write to the legacy serialized fields from this package. The 13 chapter ranges match the earlier campaign design, with a 14th catch-all for future missions. They are editorial groupings, not verified unlock rules.

## 2. Connect a verified runtime adapter

Inspect the actual local C# source and scene dependencies first. Do not select an API by similar name. Implement a `SparkAAAMissionGateway` subclass that reads the authoritative level access and result data and submits a request through the existing selector, OR add a receiver to the generated scene instance of `SparkAAAEventGateway`:

- Receiver has a public void method taking `ScriptableObject`. Verify it is the exact `ProjectSpark.Gameplay.SparkLevelDefinition` and pass it through the approved selector API. Avoid using display number or arbitrary legacy-ID strings to choose scenes.
- Assign the receiver as a dynamic event listener in `Launch Requested` and enable `Integration Approved` only after checking its code.
- From the authoritative progression subsystem, call `Publish(campaignKey, snapshot)` when real unlock/attempt/completion data changes. Example shape (not a fake unlock): `gateway.Publish(approvedKey, new SparkAAAProgress { status = verifiedStatus, fraction = verifiedFraction, rank = verifiedRank, reason = verifiedReason, canLaunch = verifiedPermission });`.
- The source supplied no real progression database or saved results. Until an adapter supplies state, cards display ACCESS NOT VERIFIED instead of guessing. The original `unlockedByDefault` is metadata, not proof of the current player's access. `ReleaseLaunchGate()` on reject, load failure or return; a handler must not silently swallow requests.
- For a subclass call `panel.SetGateway(yourVerifiedGateway)` or assign via Inspector. It is responsible for rejecting repeated launches and stale access. Dispatch events on the Unity main thread.
- Use catalog GUID and explicit approved mapping for legacy save compatibility. Level 95 is intentionally blocked by the scanner until mismatch is corrected with project-specific evidence; do not globally rename old assets or saves. Never infer migration from a suffix alone.

## 3. Existing gameplay integration checklist (requires repository)

Precisely inspect `SparkLevelDefinition.cs`, `SparkLevelSelector.cs`, `LevelGamePlayManager.cs`, `SparkLevelSceneBindings.cs`, original unlock/persistence logic, existing theme/AI interfaces, objective validators and domain managers. Preserve source asset GUIDs, current completion mode and counts. Compare old and proposed behavior on correct, incorrect, incomplete, duplicate-target, and sustained-condition examples. Map global pause, safety hold, errors, restart, scene teardown and application suspension to actual existing events. Do not fabricate authority.

Authoritative evidence should carry attempt identity, target index/approved stable ID, source, simulation tick, topology revision, repair/calibration/boot revision, unit and accepted status. Continuous conditions expire on relevant changes; historical milestones may latch. Level 130 final audit must use fresh same-boot evidence, not UI state. Confirm all domain adapters use validated data before new scoring/certification. Existing saved completions must not be revoked merely because a new certification framework is installed.

Use original save provider for commits and idempotent reward transactions; run migrations using backups and verified GUID-to-legacy identity map. The supplied `SparkAAAPreferences` only persists UI theme and selected key; does not write gameplay saves. Connect `SetTheme` to the existing approved theme event. Connect accepted mission selection and gameplay snapshots to Spark AI; it may explain data but cannot award completion or substitute for safety logic.

## 4. Visual implementation

PC: chapter navigation, paginated pooled card collection and briefing side panel; narrow layouts collapse sidebar, chapter cycle remains available, card selection opens briefing and Back returns. Test several screen sizes including phone safe areas and font scaling. Actual thumbnail capture is opt-in (select hardware prefab + number). For AAA fidelity, use existing approved workshop renders as named PNGs in generated thumbnail folder; import as single Sprite. No camera for every card. Custom shader/animated border, six-theme TMP font assignment, live shared RenderTexture viewer, sound effects and additional results panel belong to the local theme/presentation implementation after integration; they are not silently generated by this kit.
